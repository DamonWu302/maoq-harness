# MAOQ 开发路线图

[English](maoq-roadmap.md) | 中文

## 目标

本文档把 MAOQ 方向转化为可执行顺序。目标不是一个讨论股票的聊天机器人，而是一个研究与模拟交易 agent（智能体）：能够识别主要矛盾、选择阻力最小的战场、根据当前市场状态选择战术、对股票排序、给出失效条件，并接受独立风险否决。

当前重点是 **P3 战术资格**。P0 至 P2 已完成：全标签夹具、修正后的 12 份快照／10 个评估日生产 canary，以及当前本机 Codex 路由 canary 均记录在 [MAOQ 运行手册](maoq-operations.zh.md#p2-canary)中。

## 当前基础

- `maoq` Profile 已包含统帅人格和有界的 `maoq_decide` 议事组。
- 统帅可以在本机 Codex 登录与现有外部 API Key 提供方之间切换，并为新任务指定具体模型。
- 统帅可以从市场状态、情绪周期、政策与宏观、板块战场、战术选择和个股研究中动态选择不超过四位专家。
- 全新的专家、综合和风险审查 agent 生成结构化输出；独立审查者拥有最终否决权。
- 议事组逐调用报告 token 用量并汇总，绝不编造估算值。
- 不可变日级快照会生成确定性的市场状态、情绪周期和板块战场特征；规范化战略镜像支持缓存、时效核验，并在当日快照出现后自动进行收盘后维护。
- 系统仍然只做研究与模拟交易，不具备实盘下单权限。

## 产品原则

1. **以胜利为目标，以证据为约束。** 优化可复现的风险调整后结果，而不是有说服力的叙事。
2. **实事求是。** 每个结论都必须给出证据截止点、反证、置信度和失效条件。
3. **先识别主要矛盾，再选择股票。** 市场状态和板块战场决定哪些战术与候选有资格进入下一步。
4. **使用战术池，不迷信单一战法。** 趋势延续、情绪龙头、超跌反转、平台回踩、事件驱动和防守都是有条件的工具。
5. **先侦察，再集中优势兵力。** 系统从全市场逐层收敛到状态、板块、战术和个股，而不是从偏爱的股票出发。
6. **风险否决保持独立。** 不能因为逻辑诱人就放松风险约束。
7. **禁止未来数据。** 数据、板块成分、新闻和政策证据都必须能够按决策截止点复现。

| 里程碑 | 目标 | 主要交付物 | 退出标准 |

| P2 — 战略状态 | 识别市场主要矛盾和阻力最小方向 | 市场状态、情绪周期和板块战场引擎 | 每份日级快照都能产出状态、支持证据、反证和转变条件 |

## P0 — 运行基础与真实决策验证

**状态：** 已完成。本机 Codex 登录、模型选择、token 用量统计、macOS 系统代理引导、有界专家选择、结构化综合、独立风险否决、外部适配器对等性、启动／刷新引导行为和失败矩阵都有自动化证据。[MAOQ 运行手册](maoq-operations.zh.md)负责操作者 canary 和故障恢复流程。

### 范围与交付物

1. 增加 Profile 级冒烟测试，通过交付的 CLI 启动 `maoq`，而不是手工拼装测试上下文。
2. 使用**本机 Codex 登录**统帅执行一次小型工具调用，并确认模型读取工具结果后继续作答。
3. 使用一个已配置的**外部模型 API**统帅完成调用，不改变也不删除其原凭证流程。
4. 调用 `maoq_decide`，选择两位专家，再运行一位综合 agent 和一位独立风险审查 agent。
5. 按提供方、模型、角色和“用量不可用”次数记录统帅与议事组 token 用量。
6. 增加 Codex 登录缺失、模型无效、提供方超时、结构化输出畸形和风险否决等失败场景。
7. 增加一个浏览器检查，确认配置 Codex 后，启动和刷新都不会出现 API Key 引导。
8. 发布简短运行手册，覆盖启动、模型切换、诊断和恢复。

### 验收标准

- 配置 Codex 登录路由后，`pnpm dsh --profile maoq` 启动时不要求填写 API Key。
- 新建任务使用模型页面保存的提供方和模型；现有任务不会在会话中途切换。
- 统帅至少完成一次真实工具调用，并在回答前消费工具结果。
- 议事组只启动被请求的专家，并始终使用全新的综合与风险审查 agent。
- 风险否决不能被渲染为批准。
- 提供方返回的 token 用量可见；缺少用量时标记为不可用，而不是估算。
- 日志和用户可见诊断绝不包含访问 token、刷新 token 或 API Key。
- 每类失败都产生稳定、可操作的诊断，并且不能被渲染为成功决策。
- 一份已提交的无 Key 回放覆盖专家选择、结构化综合和最终风险否决；真实提供方冒烟测试覆盖交付的 CLI 路径。

## P1 — 不可变日级市场快照

**状态：** 已完成。[`dsh-market-snapshot`](../packages/market/market-snapshot/README.zh.md)负责 `MarketSnapshot` v1、确定性构建、截止点及时点校验、来源谱系、内容寻址持久化和精确身份读取。[`dsh-market-snapshot-json`](../packages/market/market-snapshot-json/README.zh.md)提供审计回放；[`dsh-market-snapshot-mysql`](../packages/market/market-snapshot-mysql/README.zh.md)消费经过质量门控的生产日线、板块、指数与情绪事实；[`dsh-market-news-web`](../packages/market/market-news-web/README.zh.md)冻结截止点前的政策与新闻证据以供精确回放。[P1 canary](maoq-operations.zh.md#p1-canary)记录真实数据库验收证据。

P1 以“实事求是”要求取得的观察与解释分离，以“没有调查，没有发言权”要求关键事实缺失时失败，以“具体问题具体分析”要求为精确日期、截止点、复权、日历、板块分类和来源设置版本。[市场快照决策](../.agents/notes/implemented/architecture/2026-08-31-maoq-market-snapshot.zh.md)负责这份映射。

### 范围与交付物

1. 定义一份带版本的 `MarketSnapshot` 文档，统一拥有身份、截止点、来源、质量状态、股票日线、时点正确的板块数据、市场宽度、情绪事实和符合截止点的新闻证据。
2. 增加确定性构建器，负责规范化源字段、验证交易日语义、排序所有无序集合、计算内容哈希并持久化不可变结果。
3. 为选定的日线、板块和新闻数据源引入适配器，不允许供应商字段名越过适配器层。
4. 按快照身份和内容哈希提供只读查询，供统帅、测试、历史回放和后续回测使用。
5. 发布 fixture 集，覆盖正常交易日、停牌、次新、退市路径、涨跌停约束、板块成分变化、数据缺失、数据冲突，以及截止点前后的新闻。

### 数据边界

- **股票日线：** 复权 OHLCV、换手率、交易状态、涨跌停状态、上市天数和数据质量标记。
- **板块日级数据：** 时点正确的成分、板块指数日线、宽度、涨停数量、上涨家数占比、领涨结构和内部离散度。
- **全市场状态：** 主要指数、总成交额、涨跌分布、连板梯队、炸板和亏钱效应指标。
- **政策与新闻证据：** 来源 URL、发布方、发布时间、抓取时间、事件时间、影响板块、置信度和明确的截止点资格。
- **快照身份：** 交易日、截止时间、交易日历版本、复权版本、板块分类版本、数据源版本和内容哈希。

### 验收标准

- 对同一日期和截止点构建两次，得到相同内容哈希。
- 停牌、次新、退市和受涨跌停限制股票都有明确语义。
- 历史板块成分满足时点正确性。
- 截止点之后发布或抓取的新闻不能进入快照。
- 关键字段缺失或冲突时，决策运行必须失败，不能静默填默认值。
- 每个持久化字段都能追溯到数据源版本或具名的确定性转换。
- 快照消费方只能得到只读数据，不能修改存储产物或重新解释其截止点。
- fixture 回放不依赖网络，并生成字节稳定的规范化输出。

## P2 — 战略状态与主要矛盾引擎

**状态：** 已完成。确定性特征、证据约束解释、有来源的毛选方法归因、独立风险否决、不可变镜像、时效失效判定、幂等收盘后维护、全标签金标覆盖、滚动生产回放和当前本机 Codex 路由 canary 均已通过。模型接收有界的前五战场加一个确定性反例，宿主仍保留全部板块特征和精确证据。

### 范围与交付物

战略层产出三个彼此连接、但可以独立测试的结果：

1. **市场状态：** 风险偏好趋势、轮动、高波动分歧、风险收缩或修复。
2. **情绪周期：** 启动、加速、高潮、分歧、退潮或修复，并由梯队高度、晋级率、炸板、亏钱效应和市场宽度支持。
3. **板块战场：** 板块强度、持续性、容量、催化支持、内部宽度、龙头质量、拥挤度和阻力。

引擎必须分离观察与解释。先计算确定性特征；模型分析负责解释主要矛盾、反证和可能的状态转变，但不能改写这些特征。

确定性层拥有特征定义、缺失数据行为、分类输入和资格边界。解释层接收一个快照身份及其已计算事实，返回结构化判断，其中包含主要矛盾、阻力最小的战场、支持证据引用、反证引用、转变条件、置信度和合格的战略姿态。最终记录同时保存两层结果，让后续评估器能够区分特征错误与推理错误。

### 验收标准

- 相同快照和引擎版本始终产生完全相同的确定性特征。
- 市场状态、情绪周期和板块战场可以分别测试，也可以分别失败。
- 每个输出状态都引用具体快照字段；模型不能引入没有引用的价格、数量、日期、板块成分或新闻事实。
- 支持证据、反证、置信度和可证伪的转变条件都是必填结构化字段。
- 每份被接受的解释都要说明至少一个获准毛选方法、其来源篇目、受证据约束的本次应用与适用边界；方法摘要必须标记为释义而不是引文。
- 陈旧、残缺或内部矛盾的快照不能产生可行动的战略姿态。
- 金标 fixture 至少覆盖每一种市场状态和情绪周期标签，并包含一组必须降低置信度或输出防守／不交易的模糊证据。
- 更换提示词或模型不能改变确定性特征；回放会单独报告解释差异。
- 本引擎不对个股排序，也不能绕过后续的战术资格和风险层。

## P3 — 战术池

**状态：** 进行中。首版注册表、失败关闭的 P2 状态门禁、时点正确的日线历史特征、共享 A 股次日开盘执行、带内容地址的 MySQL 只读历史适配器、单战法评估器以及一次读取的三战法套件审计已经实现。2022—2025 共 969 个严格质量批准交易日的首轮生产历史基线已完成：最佳趋势候选夏普 0.735，套件 PBO 40%，没有主动候选通过晋级；只有 `defensive_no_trade` 合格。第二轮优先预登记行业状态轮动与风险预算板块趋势，详见 [MAOQ P3 战法研究](maoq-p3-tactic-research.zh.md)。

| 战术族 | 适用环境 | 主要证据 | 典型失效条件 |
|---|---|---|---|
| 趋势延续与突破 | 趋势扩张且板块确认 | 相对强度、量价结构、宽度和持续性 | 突破失败或板块宽度坍塌 |
| 情绪龙头与连板梯队 | 启动或加速，晋级交易具有正收益特征 | 梯队结构、晋级率、封单和跟风响应 | 核心龙头断裂、亏钱效应扩散或晋级率坍塌 |
| 超跌反转 | 恐慌或退潮后出现可测量修复 | 抛压衰竭、背离、收复关键位和宽度修复 | 放量创新低或修复宽度失败 |
| 平台回踩与二次上攻 | 主线板块在受控整理后仍然完整 | 支撑保持、供给收缩和龙头重新走强 | 平台破位或板块领导地位改变 |
| 政策或事件驱动 | 新证据改变某板块的预期收益 | 来源质量、新颖性、传导路径、容量和价格确认 | 催化被证伪、被充分消化或缺少价格与宽度确认 |
| 防守与空仓 | 风险收缩、优势不足、证据陈旧或交易过度拥挤 | 回撤风险、流动性、离散度和不确定性 | 市场明确修复且预期收益改善 |

每种战术都是一个模块，包含资格门槛、候选特征、入场条件、退出条件、失效条件、仓位上限和评估协议。LLM（大语言模型）可以在合格战术之间选择，但不能绕过失败的确定性门槛。

## P4 — 选股与评估

候选选择遵循以下顺序：

```text
daily snapshot
  -> market regime and emotion cycle
  -> sector battlefield ranking
  -> eligible tactical modules
  -> tactic-specific candidate generation
  -> liquidity and tradability filters
  -> independent risk veto
  -> short-horizon and medium-horizon lists
```

输出必须分离短线与中线决策。短线候选侧重情绪地位、领导力、流动性、次日执行风险和快速失效条件；中线候选侧重板块持续性、趋势质量、回踩结构、催化耐久度和更宽的持有周期。系统不强迫两份名单都必须有股票。

评估使用滚动切分、时点正确的板块成分、交易成本、涨跌停限制、停牌处理和退市结果。报告胜率、盈亏比、期望收益、最大回撤、换手率、容量、分市场状态表现以及被否决交易的贡献。任何单一回测分数都不足以作为晋级依据。

## P5 — 日常运行闭环

1. 在配置的截止点之后构建并校验不可变快照。
2. 运行确定性状态与板块特征。
3. 由统帅选择最小且充分的专家议事组。
4. 产出战略状态、合格战术、候选和失效条件。
5. 应用独立的确定性风险审查和模型风险审查。
6. 只更新模拟组合，绝不发送实盘订单。
7. 结果观察窗口结束后，将决策归因到数据、状态、板块、战术、选股、执行假设和否决。
8. 监控特征漂移、战术衰减、模型变化、token 成本和不可用证据。

## 扩展形式与架构决策

MAOQ 继续作为由普通 Cordis 插件组装的 Profile；不 fork Agent 循环，也不演变为单体大插件。`dsh-maoq-app` 继续作为选择和配置能力的部署 bundle，真正的运行行为放入职责聚焦、具备测试和显式服务的包中。

- **P0 编排：** 保留 `dsh-tool-maoq-decision` 作为面向模型的议事组消费方。它协调所选 subagent 并强制执行最终否决，但不抓取市场数据，也不计算指标。
- **P1 市场事实：** MAOQ 市场快照服务负责快照类型、确定性构建、校验、持久化、只读查询和具名适配器注册表。来源专用或独立部署的采集属于单独提供方包。
- **P2 战略状态：** `dsh-market-strategic-state` 作为普通领域库计算确定性特征并校验证据约束的解释；`dsh-tool-maoq-decision` 通过 `maoq_analyze_strategy` 消费该库与快照服务。专家角色仍是运行时 agent，不是 Cordis 插件。
- **市场任务模式：** 随附的 `maoq` Agent Preset 拥有按会话收窄的人格与能力集合。它组装联网研究和用户问询，MAOQ Profile 则在全局提供快照与决策工具；编码工具继续留在标准模式。任务在第一条消息前选择预设，运行中不改变。
- **当前 UI：** `dsh-client-ui-maoq-tools` 是面向已稳定快照／决策调用记录的独立 Client Cordis 插件。bundle 负责挂载它，领域包不导入浏览器组件。
- **后续数据供应商：** 只有当替换、凭据、依赖或生命周期确实不同，才把供应商适配器拆成独立 Service Provider 包。快照 schema 和下游决策永远不依赖供应商字段名。

不要为每个指标、战术、专家角色或提示词创建一个包或插件。确定性计算器只是所属能力包中的普通模块；战术要到 P3 在独立资格判定和评估确实需要扩展点时，才成为可注册模块。这样既能让 P0–P2 在真实系统边界上可替换，又不会把内部函数变成部署单元。

## 架构边界

- LLM 负责解释证据、比较矛盾、选择合格模块并说明决策。
- 确定性服务负责截止点、特征计算、战术门槛、组合计算、风险上限和回测记账。
- 联网搜索负责提供带出处的政策与新闻证据；它不能覆盖市场数据，也不能绕过截止点。
- 市场数据适配器可替换。快照与决策约定不依赖某一家供应商的字段名。
- 在研究与模拟闭环提供稳定有效性证据、并完成独立授权设计之前，实盘券商集成不在范围内。

## 晋级门槛

只有当里程碑产物可复现、失败明确，并且测试覆盖最高风险边界时，才能进入下一阶段。战术只有在多个市场状态下通过滚动评估，并在计入成本与执行约束后仍然有效，才能从研究阶段进入模拟战术池。模型或提示词变更只有在回放与真实 canary 测试中确认结构、否决行为和证据纪律没有退化，才能晋级。

## 建议的下一步行动

从定义战术资格契约与金标 fixture 开始 P3，不要把股票排名加入 P2 引擎。模型路由、提示词、议事组结构、认证或浏览器引导发生变化时，必须保持 [P0 canary](maoq-operations.zh.md#p0-canary) 和 P2 确定性回放 fixture 通过。
