# Agent Note：最小 MAOQ 决策 Profile

状态：已实现

[English](2026-08-31-minimum-maoq-profile.md) | 中文

## 问题

有界自治运行时在扩展市场数据和战术广度之前，需要一个可执行的首个纵向切片。这个切片必须同时证明三件事：统帅动态选择专家，而不是走固定的全角色流程；每个阶段都经过结构化边界；独立风险审查者能够叫停拟议动作。同时，产品需要独立身份，但不应改写上游包名、提供者名称、许可证或归属记录。

## 决策

发布新的 `maoq` Profile，由 `dsh-base`、`dsh-web-app` 和 `dsh-maoq-app` 组成。MAOQ 层增加实事求是的统帅人格和 `maoq_decide` 工具，其权限止于研究和模拟决策。

`maoq_decide` 接收一个目标，以及从六种角色中选出的有序最小充分子集：市场状态、情绪周期、政策宏观、板块战场、战术选择和个股研究。只有被选专家并行运行。随后，一个新的综合子 Agent 返回主要矛盾、战场、战术、动作、候选、置信度和失效条件；另一个独立的新风险子 Agent 返回批准/否决、理由、硬约束和失效条件。

工作流脚本和所有输出结构都是固定部署代码。调用者不能选择提供者、改写协议、提高宿主子 Agent 上限或绕过风险阶段。宿主会校验专家报告与综合结果中的角色顺序，校验风险字段一致性，并拒绝任何把否决状态包装成批准的结果。默认 Profile 最多允许四位所选专家，并使用全新 `spawn` 子 Agent。

浏览器使用 `ui-brand-maoq` 替换面向用户的上游标志。独立的代码原生 SVG 让两股相向力量组成 `M`，标记其矛盾汇合点，并延伸出向上的路线。该包占用侧边栏和首屏 Slot；Shell 的 favicon、manifest 名称和默认标题也使用 MAOQ。为兼容与归属，技术性的 `@deepseek-ai/*` 包名、提供者集成、许可证和上游历史保持不变。

## 测试

单元测试覆盖角色选择、专家并行启动、子 Agent 上限、结构化批准与否决、矛盾否决拒绝、输入边界、提示生命周期和品牌 Slot 生命周期。无密钥真实 Loader 测试启动实际 Agent 循环、工具注册表、工作线程工作流引擎、子 Agent 接口、持久化和确定性结构化提供者。记录结果证明：选择两个角色时不会启动未选专家，能产生结构化综合，并把独立否决返回父 Agent。Profile 与 Bundle 测试固定随附组合和仅模拟决策边界。

## 后果

- MAOQ 获得可执行的命令面，同时仍是可移除插件层，而不是 Agent 循环分叉。
- 动态专家选择属于模型裁量，但受宿主拥有的角色集合和预算约束。
- 风险否决不只是提示建议；工作流返回宿主代码后仍会执行一致性校验。
- Profile 已为后续每日市场快照、联网研究、战术库和确定性组合风控留出扩展点，而不会提前授予这些权限。

## 考虑过的替代方案

- **固定六 Agent 流程图** — 否决，因为它掩盖了统帅的核心决策：当前矛盾究竟需要哪类证据；同时会把上下文和延迟花在无关角色上。
- **风险提出异议后仍由综合 Agent 批准** — 否决，因为咨询式风控无法形成独立停止边界；宿主校验使否决成为本轮最终结论。
- **改写上游包名** — 否决，因为这会破坏工作区兼容性并模糊许可证与源码归属；面向用户的身份应独立组合。

## 已知限制与延期工作

- 本切片尚未实现市场数据、板块分类、政策新闻证据和不可变每日截止时间。
- 风险审查在上下文上独立，但仍由模型给出；敞口、流动性和回撤的确定性引擎仍是未来服务。
- Profile 每次调用只做一轮议事，尚无长期市场状态日志或每日定时循环。
- 面向用户的品牌已经替换，但兼容性关键的源码包名和上游归属有意保留。
