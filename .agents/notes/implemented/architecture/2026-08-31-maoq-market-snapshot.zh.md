# Agent Note: MAOQ 不可变市场快照

Status: implemented

[English](2026-08-31-maoq-market-snapshot.md) | 中文

## 问题

如果 MAOQ 直接使用可变的实时响应来识别市场主要矛盾，就会引入未来数据、供应商耦合和不可复现的证据。后续战略解释与选股需要一份精确的日级事实集合，其来源、截止点和转换始终可检查。

## 决策

`@deepseek-ai/dsh-market-snapshot` 负责 `MarketSnapshot` 版本 1、具名供应商无关适配器注册表、确定性构建器、只追加本地持久化和只读查询服务。随附的 `maoq` bundle 把服务挂载在 `.maoq/snapshots`，并把审计 JSON 导入适配器挂载在 `.maoq/imports`。

身份组合交易日、截止点、交易日历版本、复权版本、板块分类版本和数据源版本。构建器校验记录日期和来源取得时间，按发布时间与抓取时间共同过滤新闻，检查时点正确的板块成员关系，拒绝冲突或缺失的关键事实，排序无序集合，并对规范 JSON 计算哈希。每条取得的记录都携带来源谱系和具名确定性转换。

本地存储按 SHA-256 寻址产物，并为精确的带版本身份写入单独引用。它允许幂等地重写相同字节，拒绝为现有身份写入不同内容哈希。读取会验证声明哈希并返回深度冻结值。系统有意不提供“最新快照”查询。每个适配器以唯一小写连字符名称注册，服务会拒绝身份不同于请求的返回草稿。

`@deepseek-ai/dsh-market-snapshot-mysql` 是首个生产采集适配器。它通过参数化、会话只读查询复用经过质量门控的 `long_short_stock` 数据库，而不重复请求上游 Tushare。它发现精确的质量、当日和上一日价格、复权、每日指标、涨跌停、指数和申万一级版本，在采集前后复核版本，要求连接后的每日总体等于质量结论，并且只推导确定性的板块、市场宽度与情绪事实。涨跌停表的 `pre_close` 缺失且存在上一日行情时，适配器使用精确的上一有效交易日原始收盘价并记录该转换。没有历史行情的新股仍会保留在快照中，但不进入收益率派生事实。适配器保持可选挂载，因为数据库位置与凭据属于部署事实。

`@deepseek-ai/dsh-market-news-web` 在 `ctx.web` 之上拥有独立的截止点前采集边界。搜索批次必须在截止点前开始并结束，每条接纳来源都必须具有 URL、标题和提供方给出的、不晚于截止点的发布时间，所得规范批次按内容哈希持久化。只有快照身份指定该精确 `news:<sha256>` 批次时才合并新闻。回放绝不再次联网，搜索证据也不能覆盖数据库事实。

## 毛选方法映射

“实事求是”落实为取得事实与后续解释的分离。“没有调查，没有发言权”落实为关键市场证据缺失时失败关闭。“具体问题具体分析”落实为明确的交易日、截止点、复权、板块分类和数据源版本。主要矛盾与次要矛盾的区分仍属于 P2 对这份证据的解释；P1 构建器不预测、不排序板块，也不选择股票。

## 考虑过的替代方案

**把实时提供方响应直接交给统帅。** 这会失去可复现性、接纳截止点后的证据，并让供应商词汇影响策略提示。

**每个交易日只持久化一份可变快照。** 仅有日期无法区分截止点、复权、日历、分类或来源修订，覆盖写入也会销毁早期决策使用的证据。

**让模型修补缺失或冲突数据。** 看似合理的修补并非观察事实，也会使后续评估无法区分数据失败与推理失败。

## 后果

P2 及后续阶段得到稳定、可检查的事实集合，并且必须按精确身份或内容哈希请求。新增生产供应商需要提供返回 `MarketSnapshotDraft` 的适配器；供应商字段不能进入持久化类型。JSON 适配器为外部取得的证据提供确定性无凭据导入路径，但不声称导入事实完整或有效。MySQL 适配器保留原始成交量和成交额，把换手百分数转为比率，只对价格做后复权，以最新生效记录解决重叠行业区间，并标记而不是丢弃生命周期参考滞后的有价格新股。它的股票总体是质量通过的有价格总体；完整停牌总体要等上游表具备按日质量覆盖后再实现。联网证据需要截止点前调度；即使文章本身发布更早，首次在截止点后搜索也不合格。当前本地存储假定只有一个协调写入者，而冲突检测会暴露意外的身份重新绑定。
