# Agent Note: MAOQ 不可变市场快照

Status: implemented

[English](2026-08-31-maoq-market-snapshot.md) | 中文

## 问题

如果 MAOQ 直接使用可变的实时响应来识别市场主要矛盾，就会引入未来数据、供应商耦合和不可复现的证据。后续战略解释与选股需要一份精确的日级事实集合，其来源、截止点和转换始终可检查。

## 决策

`@deepseek-ai/dsh-market-snapshot` 负责 `MarketSnapshot` 版本 1、供应商无关的适配器输入、确定性构建器、只追加本地持久化和只读查询服务。随附的 `maoq` bundle 把服务挂载在 `.maoq/snapshots`。

身份组合交易日、截止点、交易日历版本、复权版本、板块分类版本和数据源版本。构建器校验记录日期和来源取得时间，按发布时间与抓取时间共同过滤新闻，检查时点正确的板块成员关系，拒绝冲突或缺失的关键事实，排序无序集合，并对规范 JSON 计算哈希。每条取得的记录都携带来源谱系和具名确定性转换。

本地存储按 SHA-256 寻址产物，并为精确的带版本身份写入单独引用。它允许幂等地重写相同字节，拒绝为现有身份写入不同内容哈希。读取会验证声明哈希并返回深度冻结值。系统有意不提供“最新快照”查询。

## 毛选方法映射

“实事求是”落实为取得事实与后续解释的分离。“没有调查，没有发言权”落实为关键市场证据缺失时失败关闭。“具体问题具体分析”落实为明确的交易日、截止点、复权、板块分类和数据源版本。主要矛盾与次要矛盾的区分仍属于 P2 对这份证据的解释；P1 构建器不预测、不排序板块，也不选择股票。

## 考虑过的替代方案

**把实时提供方响应直接交给统帅。** 这会失去可复现性、接纳截止点后的证据，并让供应商词汇影响策略提示。

**每个交易日只持久化一份可变快照。** 仅有日期无法区分截止点、复权、日历、分类或来源修订，覆盖写入也会销毁早期决策使用的证据。

**让模型修补缺失或冲突数据。** 看似合理的修补并非观察事实，也会使后续评估无法区分数据失败与推理失败。

## 后果

P2 及后续阶段得到稳定、可检查的事实集合，并且必须按精确身份或内容哈希请求。新增生产供应商需要提供返回 `MarketSnapshotDraft` 的适配器；供应商字段不能进入持久化类型。当前本地存储假定只有一个协调写入者，而冲突检测会暴露意外的身份重新绑定。离线测试覆盖确定性回放、交易状态情形、时点成员关系、缺失与冲突数据、新闻截止点、不可变读取和身份冲突。
