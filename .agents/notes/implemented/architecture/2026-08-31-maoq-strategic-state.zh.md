# Agent Note: MAOQ 确定性战略状态与有来源的方法归因

Status: implemented

[English](2026-08-31-maoq-strategic-state.md) | 中文

## 问题

不受约束的模型可以重命名市场状态、引用决策快照中不存在的观察，并在不说明证伪条件的情况下给出貌似合理的主要矛盾。要求模型提及《毛泽东选集》又增加了归因风险：它可能虚构篇名、引文或宿主无法审计的联系。P2 需要确定性观察在提示词和模型变化时保持稳定，同时保留有用解释。

## 决策

`@deepseek-ai/dsh-market-strategic-state` 负责带版本的确定性市场状态、情绪周期和板块战场特征。它接收一个不可变当前快照和显式历史快照，排序历史，在模型执行前计算全部标签，并给每个观察分配 `snapshot:<hash>#<path>` 证据地址。三类特征分别返回就绪或不可用结果。不可用组件会阻止可行动姿态，但不会抹掉其他就绪组件。

市场状态和情绪周期使用当前市场宽度与情绪观察。板块比较需要两个使用相同分类版本的历史快照，并计算强度、持续性、容量、催化支持、内部宽度、龙头质量、拥挤度和阻力。它确定性排序板块，不输出股票排名。

独立的 `StrategicInterpretationDraft` 包含主要矛盾、阻力最小的战场、支持证据、反证、切换条件、置信度、姿态和毛选方法应用。宿主拒绝空或未知证据引用、缺失反证、无效置信度、缺少切换条件、来自过期输入的可行动输出，以及来自残缺特征的可行动输出。决策时间和最大时效都是显式回放输入；校验器不读取环境时钟。

模型只能选择获准的 `MaoMethodId`，并说明本次应用、证据和适用边界。`MAO_METHOD_CATALOG` 在校验后加入来源篇目、来源 URL 和固定中文方法摘要。每条解析结果都标记为 `paraphrase`；模型提供的篇名或所谓引文都不能成为归因。目录把《反对本本主义》《改造我们的学习》《矛盾论》《实践论》《集中优势兵力，各个歼灭敌人》和《中国革命战争的战略问题》中的分析方法映射到研究工作流，但不声称这些篇目讨论证券交易。

`maoq_analyze_strategy` 按精确哈希加载快照，并支持在同一确定性记录上进行快速或深度解释。快速模式由一个新的子 Agent 把所选角色作为综合分析视角，再运行另一个独立的新风险审查。深度模式先把确定性特征并行提供给所选专家，要求每份报告携带证据与方法引用，再运行综合和同样的独立审查。每个子输出 schema 都会枚举该份确定性特征记录中的证据地址，避免全部子调用完成后才因一个未知引用让整场议事失效；宿主校验仍是最终的失败关闭边界。宿主保留确定性标签、解析归因，并把通过校验的姿态与风险结论组合起来。较底层的 `maoq_decide` 保留用于议事组运行时诊断，不是 P2 战略决策路径。

宿主保留完整确定性记录，但向模型投影有界上下文：全部市场与情绪事实、排名最高的五个板块战场，以及排名最低的反例。发送给子 Agent 的证据对象只携带精确地址和值；冗余路径和哈希仍可从地址推导。独立审查者接收绑定标签及综合决策实际引用的证据，而不是整个特征目录。输出渲染把状态、子 Agent 数和提供方用量放在有界解释摘要之前，因此截断不会隐藏统计。模型生成的文本先在工作流边界修整首尾空白，领域校验器随后仍拒绝空文本、未知证据、缺失反证或虚构归因。这些提示形状变更会提升工作流版本，使旧镜像不能继续用于当前判断。

已完成的战略运行会发布为不可变决策镜像，其 SHA-256 身份由精确目标、快照哈希、回放时间、时效上限、专家集合、模式、特征／工作流版本、提供方路由，以及可用的 Codex 提供方设置指纹派生。缓存查询发生在快照加载或提供方解析之前。精确命中会以零新增子 Agent 返回已存状态；最新、历史和按 ID 查询工具读取同一存储，不运行模型。`maoq_state_refresh_daily` 会在建立身份前消除会话差异：宿主选择最近三个不同交易日，并固定每日目标、三种专家视角、从快照派生的决策时间和部署时效策略。可选的收盘后运行时会绑定一个未来创建的实时根 Agent，等待其空闲维护阶段，并调用与手动工具相同的每日函数。由于上游日线在上海时区 19:00 开始更新，随附策略在 19:15 首次检查，并在两小时修订窗口内每 15 分钟比较一次最新当日快照的内容哈希。只有新的可用哈希才启动分析；进程较晚启动时只补做一次检查，所属 Agent 或插件卸载时会取消仍在运行的工作。交易所休市日的工作日检查不会启动模型，因为最新快照交易日与上海日历日期不同。最新与按 ID 读取会自动解析宿主在截止时间前最新的快照，并给出独立且失败关闭的时效结论：目录无法核验、超时、快照改变、引擎／工作流漂移、分析模式漂移、提供方路由或提供方设置漂移，都会禁止当前使用，同时保留不可变历史。失败或取消的工作流绝不会发布镜像。由于快照服务尚未发布已提交构建事件，即时事件驱动刷新仍属于后续运行闭环工作。

P2 晋级会在任何当前日模型解释之前运行确定性滚动 canary。它为每个交易日选择最新快照身份，要求两个热身日加十个完整评估日，检查每个战略组件和证据目录，并反转历史输入重新计算以证明回放稳定。生产模式还要求 `long-short-stock-mysql` 来源和不可变适配器映射标记。因此，提供方到快照的字段语义属于身份：映射 v2 把主要指数 `changePct` 修正为小数比率（`0.01` 表示 1%），并生成新身份，而不是覆盖早先按百分数缩放的产物。滚动 canary 不启动 Agent，也不消耗 token；另用一次最新规范状态 canary 检查模型、归因、风险和用量。

## 考虑过的替代方案

**让统帅直接从快照 JSON 推断全部状态。** 这会让标签随提示词和模型变化，阻止独立组件测试，并混合观察与解释。

**在提示词中放入毛选篇名和引文，再接收自由文本引用。** 提示词不是归因边界；模型仍可改变篇名、释义或证据联系。特定版本逐字引文还会增加校验负担，却不能改进决策契约。

**把不可用组件压缩成 `no_trade`，不保留部分结果。** 这会隐藏市场、情绪或板块历史究竟哪一部分失败，并降低数据质量诊断和回放比较的价值。

**在 P2 内开始股票排名。** 候选评分会绕过 P3 研究和 P4 风险边界。因此 P2 止于板块排序和战略姿态。

**始终运行每位所选专家。** 这会保留最大程度的职责分离，但让常规状态检查为确定性特征引擎已经提供的信息重复支付报告成本。深度模式保留该路径；快速模式只移除这些专家报告，绝不移除独立风险审查。

## 后果

相同的有序快照哈希和引擎版本会产生字节一致的确定性特征；提示词或模型变化只能影响分开存储的解释。每份被接受的解释都会给出支持与反对的快照字段、可证伪切换条件、置信度，以及至少一个有来源的方法应用。快速模式把战略子 Agent 数固定为两个，深度模式则为每位所选专家增加一个子 Agent；两种模式都保留最终独立否决。完全相同的重复请求会变成文件系统读取并报告 `agentsStarted: 0`；历史复盘不再重复运行议事组。缺失历史、过期输入或虚构引用都会失败关闭。阈值是显式引擎策略：改变阈值需要提升版本并更新金标夹具。固定归因目录提高了可审计性，但有意放弃逐字引文和版本页码。盘中状态仍不属于该日级契约。

十日生产门禁需要十二个不同交易日，并有意与模型质量评估分离。这样可以低成本地在历史窗口中发现字段单位或确定性回归；只要确定性引擎或映射版本没有变化，提示词或提供方变更只需运行一次当前路由规范状态 canary。

2026-09-01 的有界本机 Codex canary 使用两个 Agent、合计 64,411 个子调用 token，且零用量不可用调用，比早先全板块提示约低 74%。这仍是每个身份只支付一次的解释成本；完全相同的重复请求不启动子 Agent，直接读取不可变镜像。
