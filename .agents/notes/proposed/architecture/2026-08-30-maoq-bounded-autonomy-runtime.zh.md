# Agent Note: MAOQ 决策的有界自治运行时

Status: proposed

[English](2026-08-30-maoq-bounded-autonomy-runtime.md) | 中文

## Problem

MAOQ 需要一个能够选择研究路径、委派工作、消解证据冲突并在没有固定编排图的情况下形成选股决策的 Agent 运行时。无限制的自治不适合交易：模型在做出决策时不得修改市场数据截止时间、风险限制、执行权限或生产策略代码。

量化领域逻辑继续归属于独立的 `maoq-agent` 仓库。这个 Fork 必须提供编排和运行时策略，同时避免重复市场计算，也不能把 MAOQ 需求变成通用 Agent Loop 中的特殊分支。

## Proposal

MAOQ 将作为基于源码构建的 DSH Profile 交付，它组合现有的会话、子 Agent、联网、工作流、守卫和交互能力，并挂载 MAOQ 自有插件。Profile 可以动态选择工具和子 Agent，但由模型控制范围之外的确定性服务强制执行资源预算、数据时间边界、风险规则和执行权限。

首个实现只使用已记录的插件扩展点。只有必需行为无法通过插件表达时才允许修改核心，并且每个此类补丁都必须包含聚焦的回归测试和说明缺失扩展点的记录。通用 Agent Loop 不得包含市场术语或策略规则。

运行时将向 Python 领域服务公开一个结构化决策操作。一次决策运行把不可变的市场数据快照、新闻证据快照、策略版本和运行时版本绑定到唯一决策标识。同一标识的重试不得生成第二份已提交决策或执行请求。

统帅 Agent 可以选择需要运行的专业 Agent，并且可以在新增研究的预期价值较低时停止。首批专业角色覆盖政策与宏观证据、新闻核验、市场状态、短线情绪周期、板块战场排序、战术选择、个股研究和对抗式风险复核。这些角色是统帅可选的能力，而不是每次运行必须全部调用的固定清单。

专业 Agent 返回经过 Schema 校验的主张，其中包含证据引用、观察时间、置信度、反方证据和失效条件。聚合过程依据证据质量和数据新鲜度解决矛盾，不对多份文字报告进行多数投票。所有模型可见输入和已提交结论都必须能够从会话日志重建，而权威市场事实和决策账本继续存放在领域数据库中。

生产 Profile 禁用运行时自我修改，并且研究 Agent 不得获得券商凭证。独立的研究 Profile 可以提出代码或策略补丁，但晋升需要测试和明确的人工批准。首个实现不包含实盘执行；只有具备账户级限制、幂等控制和紧急停止后，才可以增加确定性执行器。

交易日历自动化继续由外部服务负责。该服务使用明确的快照和截止时间启动或恢复 DSH 运行；会话内的间隔调度器不负责交易时段、节假日或漏跑恢复。

### Autonomy levels

- Level 0 提供只读分析，不允许委派。
- Level 1 允许自主研究、联网收集证据和有预算限制的子 Agent 委派。
- Level 2 在确定性风险校验后允许自主生成候选和模拟决策。
- Level 3 只有在另一项决策批准该能力后，才可以提交受约束的实盘执行请求。
- 所有等级都排除生产环境自我修改行为。

### Initial implementation slice

首个切片增加一个 MAOQ Profile 和完成一次决策所需的最少插件，不修改通用 Agent Loop。它验证动态选择专业 Agent、结构化输出、独立风险否决、事件持久化、恢复、取消和 Python 调用方。包边界将依据实际的独立演进需求划分，不会预先为每个概念角色创建一个包。

Python 服务负责市场计算、战术定义、候选排序、组合状态和权威决策事务。DSH 负责 Agent 执行、模型与工具选择、委派上下文、会话事件、取消和运行时遥测。两者通过狭窄的版本化协议集成，不在两个仓库之间直接导入源码。

## Alternatives considered

**在 DSH 内实现完整决策引擎。** 这会把 TypeScript 运行时与量化研究耦合并重复 Python 计算，也会因为市场行为扩散到通用运行时包而增加同步上游的难度。

**保持上游 DSH 不变并且只配置提示词。** 仅靠提示词组合无法可靠强制执行幂等、风险否决、证据字段、工具权限或持久决策生命周期规则。

**Fork 后重写 Agent Loop。** 私有 Loop 可以提供最大自由度，但会放弃插件架构、增加合并冲突，并使运行时正确性依赖一组庞大的永久补丁。

**每次决策都运行全部专业 Agent。** 固定图容易观察，但会在无关问题上消耗时间和 Token，并阻止统帅根据不确定性分配研究资源。

**允许生产 Agent 修改自己的插件。** 这会缩短实验周期，但也允许未经评估的改动在提出它的同一进程中改变权限或决策行为。

## Acceptance criteria

- 从本仓库源码构建的 MAOQ Profile 可以启动，并通过 Python SDK 或协议客户端完成一次决策。
- 统帅在运行时从至少三个专业 Agent 中选择，并且一个记录案例证明它可以省略无关角色。
- 每个专业 Agent 的结果和最终决策都通过 JSON Schema 校验，并保留证据时间、来源、反方证据和失效条件字段。
- 确定性风险服务可以拒绝模型认可的候选，并且被拒绝的动作无法到达执行适配器。
- 在超时、取消和进程重启后，重复使用决策标识仍然保持幂等。
- 会话重放可以重建 Agent 可见证据和结论，而领域数据库继续作为事实、组合状态和已提交决策的权威来源。
- 工具过滤、委派深度、并行子 Agent 数量、模型成本、运行时间和联网权限均可配置，并且达到限制时采取闭锁失败。
- 生产 Profile 不包含自我修改工具或券商凭证；首个切片无法下达实盘订单。
- 聚焦的组合测试覆盖真实 Profile，一个无密钥的会话录制快照覆盖模型可见决策路径。
- 合并上游 `master` 时不需要解决通用 Agent Loop 内的市场领域改动。

## Risks

动态委派可能产生不确定性并增加成本。因此运行时记录选择原因、应用硬预算，并通过可重放的结果评估决策，而不要求推理文字完全相同。

分离 DSH 事件和领域账本会形成两套持久化系统。唯一决策标识和明确的提交结果可以避免权属模糊；会话事件解释运行过程，领域事务决定某项决策是否存在。

仅使用插件的实现可能暴露真正缺失的扩展点。相比在提示词中模拟生命周期保证，最小且经过测试的核心修改更可靠；但每个核心补丁都会增加同步上游的成本，并且不得包含市场领域策略。
